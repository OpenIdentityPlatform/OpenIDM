[#appendix-ro-install]
== Installing OpenIDM on a Read-Only Volume

Keep the binary distribution on a read-only filesystem and put the OpenIDM project, runtime files, and logs on writable filesystems. This procedure assumes Linux, a service user and group named `idm`, and an external JDBC repository as described in xref:chap-repository.adoc#chap-repository[Installing a Repository For Production].

[#ro-install-volumes]
=== Prepare the Installation

. Mount the dedicated installation volume at `/idm`. For example, the entry for an ext4 filesystem in `/etc/fstab` has six whitespace-separated fields:
+
[source,text]
----
/dev/volume  /idm  ext4  defaults,ro  0  2
----
+
Substitute your device or filesystem UUID and verify the entry against your system's mount configuration.
. Mount the volume read-write during installation and unpack the release ZIP. Substitute its actual filename:
+
[source,bash]
----
sudo mount -o remount,rw /idm
sudo unzip /path/to/openidm-version.zip -d /idm
sudo install -d -o idm -g idm -m 0700 /var/lib/openidm/project
sudo install -d -o idm -g idm -m 0700 /var/lib/openidm/run
sudo install -d -o idm -g idm -m 0700 /var/cache/openidm/felix-cache /var/cache/openidm/classes
sudo install -d -o idm -g idm -m 0700 /var/log/openidm/logs /var/log/openidm/audit
sudo cp -a /idm/openidm/conf /var/lib/openidm/project/
sudo cp -a /idm/openidm/security /var/lib/openidm/project/
sudo chown -R idm:idm /var/lib/openidm/project
----
+
Copy your project's scripts, workflow definitions, and other custom files into the writable project directory. Use this directory for the JDBC repository and datasource configuration.

[#redirect-openidm-writes]
=== Redirect Runtime Files

Set these paths in the writable project under `/var/lib/openidm/project`:

* In `conf/boot/boot.properties`, set `openidm.keystore.location` and `openidm.truststore.location` to absolute paths in the writable project's `security/` directory. Check that the service user can read and write the selected stores.
* In `conf/audit.json`, set `logDirectory` inside the JSON handler's `config` object to `/var/log/openidm/audit`. The packaged configuration uses `org.forgerock.audit.handlers.json.JsonAuditEventHandler`. Apply equivalent paths to any additional file-based audit handlers.
* In `conf/logging.properties`, set `java.util.logging.FileHandler.pattern=/var/log/openidm/logs/openidm%u.log`.
* If you use Groovy compilation, set `groovy.target.directory` in the `Groovy` object of `conf/script.json` to `/var/cache/openidm/classes`. Point file-based connectors and other custom components at writable locations for their data and output.

[#ro-install-final]
=== Start and Verify

Start as the service user and pass the writable Felix cache directory with `-s`. Set the PID file path in the service environment and keep it set when invoking `shutdown.sh`.

[source,bash]
----
export OPENIDM_PID_FILE=/var/lib/openidm/run/openidm.pid
/idm/openidm/startup.sh -p /var/lib/openidm/project -s /var/cache/openidm/felix-cache
----

Before remounting the installation, check that Felix created `bundle0` under the external cache.

[source,bash]
----
test -d /var/cache/openidm/felix-cache/bundle0
----

Once startup and the cache check succeed, stop OpenIDM and remount the installation volume read-only.

[source,bash]
----
sudo mount -o remount,ro /idm
----

Restart with the same `-p` and `-s` options and PID file environment. Verify that OpenIDM reaches `ACTIVE_READY`, can read and update the JDBC repository, and writes audit and application logs into their configured directories. Check that the mount is read-only and review the startup log for write failures.
