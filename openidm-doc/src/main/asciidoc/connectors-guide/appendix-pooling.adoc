== Connection Pooling Configuration

OpenICF reuses instances of connectors that support pooling. When an operation needs an instance, OpenICF borrows an idle instance or creates one if the pool has capacity. It returns the instance to the pool when the operation ends. For an unpooled connector, OpenICF creates and disposes of an instance for each operation.

Set the top-level `poolConfigOption` object in the provisioner JSON for a poolable connector. The settings apply where the connector runs, locally in OpenIDM or on the remote connector server.

[cols="2,1,5",options="header"]
|===
|Property |Default |Effect
|`maxObjects` |10 |Maximum number of active and idle instances combined.
|`maxIdle` |10 |Maximum number of idle instances to retain. Use `0` to dispose of instances as they return.
|`maxWait` |150000 |Wait limit for a free instance when the pool has reached capacity. OpenICF for Java 2.0.4 uses seconds. OpenICF.Net 1.5.0 uses milliseconds. Use `0` to fail immediately if no instance is available.
|`minEvictableIdleTimeMillis` |120000 |Idle age in milliseconds (120 seconds by default) after which an idle instance is eligible for eviction.
|`minIdle` |1 |Idle-instance floor used when checking for eviction on a Java borrow or when the .NET pool evicts aged instances. The pools create instances as needed.
|===

Use nonnegative integers with `minIdle <= maxIdle <= maxObjects`. The following Java connector example sets a 15-second wait limit.

[source,json]
----
{
  "poolConfigOption": {
    "maxObjects": 10,
    "maxIdle": 10,
    "maxWait": 15,
    "minEvictableIdleTimeMillis": 120000,
    "minIdle": 1
  }
}
----

The Java link:https://github.com/OpenIdentityPlatform/OpenICF/blob/2.0.4/OpenICF-java-framework/connector-framework-internal/src/main/java/org/identityconnectors/framework/impl/api/local/ObjectPool.java[`ObjectPool`] and .NET link:https://github.com/OpenIdentityPlatform/OpenICF.Net/blob/1.5.0/FrameworkInternal/ApiLocal.cs[pool implementation] define the wait units.
