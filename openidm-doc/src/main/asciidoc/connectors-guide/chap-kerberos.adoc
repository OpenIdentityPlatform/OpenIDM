[#chap-kerberos]
== Scripted Kerberos Connector

The Kerberos connector manages principals through the MIT Kerberos `kadmin` command-line tools over SSH. OpenIDM includes `connectors/kerberos-connector-<version>.jar` and its `ssh-connector` dependency. In `connectorRef`, use the bundle name `org.openidentityplatform.openicf.connectors.kerberos-connector` and the class `org.forgerock.openicf.connectors.kerberos.KerberosConnector`.

The assembly extracts the ready-made operation scripts from the Kerberos connector JAR into the sample project. Use those scripts to list and read principals, create and delete them, change passwords, and unlock accounts. See xref:../samples-guide/chap-kerberos-sample.adoc#chap-kerberos-sample[the Kerberos sample] for an end-to-end example.

[#ssh-kerberos-schema]
=== Kerberos Connector Schema

The provisioner's `account` type maps to the OpenICF `__ACCOUNT__` type. The sample maps the `principal` property to `__NAME__` and uses the complete principal name, including the realm, as the OpenICF `__UID__`.

[cols="2,5",options="header"]
|===
|Attribute |Use
| `__PASSWORD__` | Supply a password on create. Include a new password in an update to change it.
| `__LOCK_OUT__` | Set to `false` in an update to unlock the principal.
| `policy` | Name of the Kerberos password policy. The create script can set it.
| `expirationDate`, `passwordExpiration` | Principal and password expiration dates. Use the string syntax accepted by `kadmin` when creating a principal.
| `maximumTicketLife`, `maximumRenewableLife` | Ticket lifetime and maximum renewable lifetime. Use the duration syntax accepted by `kadmin` when creating a principal.
| `lastPasswordChange`, `lastModified`, `lastSuccessfulAuthentication`, `lastFailedAuthentication`, `failedPasswordAttempts` | Read-only string fields parsed from `getprinc` output.
|===

The bundled update script handles password changes and unlocks. Changes to the name, policy, expiration dates, and lifetimes require a different update script.

[#ssh-kerberos-config]
=== Configuring the Kerberos Connector

. Copy `samples/kerberos/conf/provisioner.openicf-kerberos.json` into your project's `conf/` directory and copy `samples/kerberos/tools/script/kerberos/` into `tools/script/kerberos/`.
. Set the SSH host, login, password or key, and shell prompt as described in xref:chap-ssh.adoc#ssh-authentication[Configuring Authentication to the SSH Server]. The SSH user runs the command on the remote host. Configure the Kerberos administrative principal separately. Apply the SSH connector's host verification and timeout guidance.
. Configure password-prompting `sudo` on the SSH host for the configured administration command. The bundled scripts call the SSH `sudo` helper and parse English command output. Set a consistent shell prompt and command locale on that host.
. Configure the command and realm in the following properties. After startup, use `POST /openidm/system/kerberos?_action=test` to exercise the `list_policies` command, and `GET /openidm/system/kerberos/account?_queryId=query-all-ids` to test principal listing.

[#customConfiguration]
==== `customConfiguration`

Set `kadmin.cmd` to the absolute path to the Kerberos command on the SSH host. Use `kadmin.local` on a host with local access to the KDC database, as in the sample, or `kadmin` to connect to the remote administration service. Set `kadmin.user` to the administrative principal. The create and update scripts append `kadmin.default_realm` to principal names that omit the realm.

[source,json]
----
{
  "customConfiguration": "kadmin { cmd = '/usr/sbin/kadmin.local'; user = 'openidm/admin'; default_realm = 'EXAMPLE.COM' }"
}
----

[#customSensitiveConfiguration]
==== `customSensitiveConfiguration`

When using `kadmin`, supply the administrative principal password as `kadmin.password` in this confidential property. This is separate from the SSH user's password. `kadmin.local` uses local access to the KDC database.

[source,json]
----
{
  "customSensitiveConfiguration": "kadmin { password = '<KADMIN PASSWORD>' }"
}
----

[#sec-implemented-interfaces-org-forgerock-openicf-connectors-kerberos-KerberosConnector-1_4_0_0]
=== OpenICF Interfaces Implemented by the Kerberos Connector

The bundled scripts provide create, delete, search, schema, test, and update through the xref:chap-groovy.adoc#sec-implemented-interfaces-org-forgerock-openicf-connectors-groovy-ScriptedConnector-1_4_2_1[shared Groovy interfaces]. The schema disables Authenticate, Resolve Username, and Sync for accounts. The Script on Resource file is a stub. The connector inherits Groovy Script on Connector and SSH instance pooling.

Search supports an unfiltered principal list and equality, starts-with, ends-with, and contains filters on the principal name. Use the full realm-qualified principal for reads, updates, and deletes. In REST URLs, encode the principal as a single path segment, for example `kadmin%2Fadmin%40EXAMPLE.COM`.

[#sec-config-properties-org-forgerock-openicf-connectors-kerberos-KerberosConnector-1_4_0_0]
=== Kerberos Connector Configuration

[#configuration-properties-org-forgerock-openicf-connectors-kerberos-KerberosConnector-1_4_0_0]
==== Configuration Properties

The connector exposes the same configuration property set as the xref:chap-ssh.adoc#sec-config-properties-org-forgerock-openicf-connectors-ssh-SSHConnector-1_4_0_0[SSH Connector]. The Kerberos scripts read the administrator settings from the shared Groovy properties `customConfiguration` (String) and `customSensitiveConfiguration` (GuardedString). Both default to unset. Set the command, administrator and realm for the bundled scripts, and set the sensitive property when the command prompts for the Kerberos password.

[#operation-script-files-properties-org-forgerock-openicf-connectors-kerberos-KerberosConnector-1_4_0_0]
==== Operation Script Files Properties

Keep the shipped sample's script filenames and match them to the link:https://github.com/OpenIdentityPlatform/OpenICF/tree/2.0.4/OpenICF-kerberos-connector/src/main/resources/script/kerberos[bundled Kerberos scripts]. The same xref:chap-ssh.adoc#operation-script-files-properties-org-forgerock-openicf-connectors-ssh-SSHConnector-1_4_0_0[operation script properties] are available as for the SSH connector.

[#groovy-engine-configuration-properties-org-forgerock-openicf-connectors-kerberos-KerberosConnector-1_4_0_0]
==== Groovy Engine Configuration Properties

Set `scriptRoots` to the directory containing the scripts. The sample uses `["&{launcher.project.location}/tools/script/kerberos/"]`. See xref:chap-ssh.adoc#groovy-engine-configuration-properties-org-forgerock-openicf-connectors-ssh-SSHConnector-1_4_0_0[the inherited Groovy settings].

[#basic-configuration-properties-properties-org-forgerock-openicf-connectors-kerberos-KerberosConnector-1_4_0_0]
==== Basic Configuration Properties

Use the xref:chap-ssh.adoc#configuration-properties-org-forgerock-openicf-connectors-ssh-SSHConnector-1_4_0_0[inherited SSH settings] for the host, authentication, prompt, and timeouts. Use the provisioner's `poolConfigOption` to control the SSH instance pool.
