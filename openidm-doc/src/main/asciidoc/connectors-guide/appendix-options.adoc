[#appendix-options]
== OpenICF Operation Options

The sections below use the option names defined by the Java `OperationOptions` API. The connector schema reports which options a connector supports. OpenIDM maps REST query parameters such as `_pageSize`, `_pagedResultsCookie`, `_pagedResultsOffset`, `_sortKeys`, and `_fields` to connector options where applicable.

[#operation-option-scope]
=== Scope

`SCOPE` is a string that specifies the search scope relative to xref:#operation-option-container[Container].

* `object` (`SCOPE_OBJECT`) matches the container itself.
* `onelevel` (`SCOPE_ONE_LEVEL`) searches its immediate children.
* `subtree` (`SCOPE_SUBTREE`) searches below it. Consult the connector for how it handles the base object.

[#operation-option-container]
=== Container

`CONTAINER` is the `QualifiedUid` of the container in which to search. A `QualifiedUid` includes the object class and unique identifier.

[#operation-option-run-as-user]
=== Run as User

`RUN_AS_USER` is a string identifying the account under which a supported operation, such as Script on Resource, executes.

[#operation-option-run-with-password]
=== Run with Password

`RUN_WITH_PASSWORD` is a `GuardedString` credential for the Run as User account when the connector supports it.

[#operation-option-attributes-to-get]
=== Attributes to Get

`ATTRS_TO_GET` is an array of attribute names to request from Search or Sync. It can request a subset of the default attributes or include additional attributes. The connector schema indicates which attributes are returned by default.

[#operation-option-paged-results-cookie]
=== Paged Results Cookie

`PAGED_RESULTS_COOKIE` is an opaque string. For cookie-based paging, pass the cookie returned by the previous search to continue that search. The initial request omits the cookie, and a null result cookie indicates the last page.

[#operation-option-paged-results-offset]
=== Paged Results Offset

`PAGED_RESULTS_OFFSET` is an integer identifying the first result to return when a connector supports offset-based paging. In the Java API the first result is at offset `1`. An omitted or lower offset requests the next page in the connector's paging sequence.

[#operation-option-page-size]
=== Page Size

`PAGE_SIZE` sets the requested page size as an integer in Search. Omit it or use `0` for an unpaged request.

[#operation-option-total-paged-results-policy]
=== Total Paged Results Policy

`TOTAL_PAGED_RESULTS_POLICY` is the Java API's `CountPolicy`. Use `NONE` (the default) for no count, `ESTIMATE` to allow an estimate, or `EXACT` to request an exact count. Consult the returned policy in the `SearchResult` to determine what the connector provided.

[#operation-option-sort-keys]
=== Sort Keys

`SORT_KEYS` is an array of `SortKey` values, each identifying a field and its sort direction.

[#operation-option-fail-on-error]
=== Fail on Error

`FAIL_ON_ERROR` is a boolean for the Java Batch API. Set it to `true` to request that processing stop on the first error. The default is `false`.

[#operation-option-require-serial]
=== Require Serial

`REQUIRE_SERIAL` requests that a native batch implementation execute tasks sequentially where supported. The Java `OperationOptions` getter reads it as a string (`"true"` or `"false"`) and defaults to `false`. The local Java fallback always executes tasks sequentially.

See the link:https://github.com/OpenIdentityPlatform/OpenICF/blob/2.0.4/OpenICF-java-framework/connector-framework/src/main/java/org/identityconnectors/framework/common/objects/OperationOptions.java[`OperationOptions` source] for the option types and constants.
