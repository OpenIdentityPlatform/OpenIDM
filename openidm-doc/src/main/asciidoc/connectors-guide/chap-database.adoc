[#chap-database]
== Database Table Connector

OpenIDM ships `connectors/databasetable-connector-<version>.jar` to manage accounts in a single JDBC table. Each row is an account. The configured key column supplies `__UID__` and `__NAME__`, and the connector discovers the remaining attributes from JDBC column metadata.

[#database-connector-config]
=== Configuring the Database Table Connector

Use `samples/provisioners/provisioner.openicf-contractordb.json` as a template. The accompanying `provisioner.openicf-contractordb.sql` creates the MySQL sample schema and the `people` table. For an existing table, choose a unique, non-null key and grant the connector's database account the privileges needed for the intended operations. For a read-only import, grant `SELECT`. For provisioning, also grant the required `INSERT`, `UPDATE`, and `DELETE` privileges.

For the local connector, place a JDBC driver for the database in `openidm/lib/` if it is absent, then restart OpenIDM to load it. The example uses `com.mysql.cj.jdbc.Driver` from link:https://dev.mysql.com/downloads/connector/j/[MySQL Connector/J]. For a remote Java connector server, install the driver on that server and set `connectorHostRef` to its configured reference.

Copy the sample to the active project's `conf/` directory and adapt its settings. The following example uses the sample table with a dedicated database user. Set `contractordb.password` through xref:../integrators-guide/chap-configuration.adoc#using-property-substitution[property substitution] or update the password through the Admin UI.

[source,json]
----
{
  "connectorRef": {
    "bundleName": "org.openidentityplatform.openicf.connectors.databasetable-connector",
    "bundleVersion": "[2.0.0.0,3)",
    "connectorName": "org.identityconnectors.databasetable.DatabaseTableConnector"
  },
  "configurationProperties": {
    "host": "127.0.0.1",
    "port": "3306",
    "user": "openidm_contractors",
    "password": "&{contractordb.password}",
    "database": "contractordb",
    "table": "people",
    "keyColumn": "UNIQUE_ID",
    "jdbcDriver": "com.mysql.cj.jdbc.Driver",
    "jdbcUrlTemplate": "jdbc:mysql://%h:%p/%d"
  }
}
----

Set JDBC URL parameters as required by your driver, including encrypted transport and certificate verification for remote connections. Test the connection and verify the generated account schema before configuring a mapping. The connector reports the account object class as `__ACCOUNT__`. Use the actual object type name in your provisioner when you access it through OpenIDM.

[#database-connector-livesync]
=== Detecting Changed Rows

To use LiveSync, set `changeLogColumn` to a column whose values increase as rows change. The connector selects rows with values strictly greater than the last token and processes them in ascending order. Ensure later changes receive greater values, including updates made outside OpenIDM. If changes can share a timestamp and a poll is interrupted, rows sharing the last processed value can be missed. A sequence that advances on each change avoids tied values.

The sample `CHANGE_TIMESTEMP` column defaults to the insertion time. For that column to track updates, arrange for the database or every writer to set it on update as well. The connector emits create-or-update events from current rows. Use reconciliation to detect physical deletes.

[#sec-implemented-interfaces-org-identityconnectors-databasetable-DatabaseTableConnector-1_1_0_2]
=== OpenICF Interfaces Implemented by the Database Table Connector

The Database Table Connector implements the following OpenICF interfaces.
--

xref:appendix-interfaces.adoc#interface-AuthenticationApiOp[Authenticate]::
Matches the supplied user name and password against `keyColumn` and `passwordColumn`. Set `passwordColumn` to enable this operation.

xref:appendix-interfaces.adoc#interface-CreateApiOp[Create]::
Creates an object and its `uid`.

xref:appendix-interfaces.adoc#interface-DeleteApiOp[Delete]::
Deletes an object, referenced by its `uid`.

xref:appendix-interfaces.adoc#interface-ResolveUsernameApiOp[Resolve Username]::
Resolves an object by its username and returns the `uid` of the object.

xref:appendix-interfaces.adoc#interface-SchemaApiOp[Schema]::
Describes the object types, operations, and options that the connector supports.

xref:appendix-interfaces.adoc#interface-ScriptOnConnectorApiOp[Script on Connector]::
Enables an application to run a script in the context of the connector. Any script that runs on the connector has the following characteristics:
+

* The script runs in the same execution environment as the connector and has access to all the classes to which the connector has access.

* The script has access to a `connector` variable that is equivalent to an initialized instance of the connector. At a minimum, the script can access the connector configuration.

* The script has access to any script-arguments passed in by the application.


xref:appendix-interfaces.adoc#interface-SearchApiOp[Search]::
Searches the target resource for all objects that match the specified object class and filter.

xref:appendix-interfaces.adoc#interface-SyncApiOp[Sync]::
Uses `changeLogColumn` to return inserted and updated rows.

xref:appendix-interfaces.adoc#interface-TestApiOp[Test]::
Validates the configuration and connects to the database.

xref:appendix-interfaces.adoc#interface-UpdateApiOp[Update]::
Updates (modifies or replaces) objects on a target resource.

--


[#sec-config-properties-org-identityconnectors-databasetable-DatabaseTableConnector-1_1_0_2]
=== Database Table Connector Configuration

The Database Table Connector has the following configurable properties.

[#configuration-properties-org-identityconnectors-databasetable-DatabaseTableConnector-1_1_0_2]
==== Configuration Properties


[cols="2,1,2,4",options="header"]
|===
|Property |Type |Default |Purpose
|`quoting` |String |Empty |Quote column identifiers in generated SQL. Values are `none`, `single`, `double`, `back` (backticks), and `brackets`. An empty string is equivalent to `none`.
|`host` |String |Empty |Database host. Required with a direct JDBC URL containing `%h`.
|`port` |String |Empty |Database port. Required with a direct JDBC URL containing `%p`.
|`user` |String |Empty |Database login. With a JNDI data source, the connector uses supplied credentials only when both a nonblank user and a password are set.
|`password` |Guarded string |Unset |Confidential database login password. Supply a value for a direct JDBC connection.
|`database` |String |Empty |Database name. Required with a direct JDBC URL containing `%d`.
|`table` |String |Empty |Required table name. Supply any necessary schema qualification and quoting for the table name.
|`keyColumn` |String |Empty |Required unique, non-null identifier column for accounts. Use a separate column for passwords and for change tracking.
|`passwordColumn` |String |Empty |Column mapped to `__PASSWORD__`. Set it to enable password writes and connector authentication.
|`jdbcDriver` |String |`oracle.jdbc.driver.OracleDriver` |Fully qualified JDBC driver class for a direct connection. Set it to match the installed driver.
|`jdbcUrlTemplate` |String |`jdbc:oracle:thin:@%h:%p:%d` |JDBC connection URL. `%h`, `%p`, and `%d` substitute the host, port, and database. Use `%%` for a literal percent sign. Keep this setting nonempty when using a JNDI data source, even though the connection uses `datasource`.
|`enableEmptyString` |Boolean |`false` |Substitute an empty string for a null value in a required string column where the database supports it.
|`rethrowAllSQLExceptions` |Boolean |`true` |Set to `false` to suppress SQL exceptions with vendor error code zero where the connector applies this setting.
|`nativeTimestamps` |Boolean |`false` |Read timestamp columns using the JDBC driver's native timestamp access instead of its string conversion.
|`allNative` |Boolean |`false` |Use native JDBC types for all supported columns.
|`validConnectionQuery` |String |Unset |Optional SQL query for testing a pooled connection. By default, the connector toggles autocommit to test the connection.
|`changeLogColumn` |String |Empty |Column that stores the change sequence or timestamp. Required for LiveSync.
|`datasource` |String |Empty |JNDI name of a JDBC `DataSource`, such as `jdbc/Contractors`. When supplied, the connector obtains connections from this data source instead of the JDBC URL.
|`jndiProperties` |Array of strings |Unset |JNDI environment properties as `key=value` strings for the data source lookup.
|`suppressPassword` |Boolean |`true` |Keep the password out of read results. Setting this to `false` allows an explicit request to return it.
|===
