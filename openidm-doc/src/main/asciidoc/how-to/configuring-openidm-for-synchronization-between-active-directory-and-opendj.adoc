== Configuring OpenIDM for Synchronization Between Active Directory and OpenDJ

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-introduction]]
=== Introduction

In this article we will configure two-way synchronization between Active Directory and OpenDJ. Changes made in Active Directory will be synchronized to OpenDJ and vice versa.

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-configuring-openidm]]
=== Configuring OpenIDM

Start with a dedicated OpenIDM deployment and separate test directories with backups. The mappings include reconciliation actions that delete entries. Review the mapping filters and linked mappings before executing them. Use `Ignore` for deletion situations during an initial preview. See xref:../install-guide/index.adoc[Installing OpenIDM].

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-configuring-the-data-sources]]
=== Configuring the data sources

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-configuring-active-directory]]
==== Configuring Active Directory

Copy `samples/provisioners/provisioner.openicf-adldap.json` from your release to the OpenIDM project’s `conf` directory. Configure the JVM truststore as described in xref:active-directory-identity-management.adoc#active-directory-identity-management-active-directory-connector-configuration[Active Directory Connector Configuration].

Modify the properties to match your Active Directory server settings:

[cols=",",options="header",]
|===
|Setting |Description
|host |DNS name matching the domain controller certificate, for example `ad.example.com`
|port |`636` for LDAPS
|ssl |`true`
|principal |Dedicated bind account with delegated permissions on the test OU, e.g. `"CN=svc-openidm,CN=Users,DC=example,DC=com"`.
|credentials |Account password
|baseContexts |A list of DNs containing accounts to synchronize, e.g. `++[++"CN=Users,DC=Example,DC=com"++]++.`
|baseContextsToSynchronize |Identical to `baseContexts`
|accountSearchFilter |A filter to search for accounts
|accountSynchronizationFilter |Filter for account synchronization.
|===

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-configuring-opendj]]
==== Configuring OpenDJ

If you do not have OpenDJ installed, install it as described in the https://doc.openidentityplatform.org/opendj/install-guide[documentation].

Use `samples/sample2b/data/Example.ldif` from your OpenIDM distribution for the OpenDJ test directory.

Perform the initial configuration of OpenDJ and import the data using the following command:

....
 cd /path/to/opendj

 ./setup --cli \
--hostname localhost \
--ldapPort 1389 \
--rootUserDN "cn=Directory Manager" \
--rootUserPassword password \
--adminConnectorPort 4444 \
--baseDN dc=com \
--ldifFile /path/to/openidm/samples/sample2b/data/Example.ldif \
--acceptLicense \
--no-prompt
...
Configuring Directory Server ..... Done.
Creating Base Entry dc=com ..... Done.
Starting Directory Server ....... Done.
...
....

Copy `samples/provisioners/provisioner.openicf-ldap.json` from the same OpenIDM release to the project’s `conf` directory. Keep its name `ldap`. Set the credentials to the password chosen during OpenDJ setup. Test both connectors in the Admin UI and make sure each source lists the expected test accounts.

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-configuring-active-directory--opendj-synchronization]]
=== Configuring Active Directory → OpenDJ synchronization

Open the OpenIDM administrator console at http://localhost:8080/admin. Login with the username `openidm-admin` and password `openidm-admin`. In the top menu, navigate Configure → Mappings and create Mapping ad → user as shown in the figure below.

image:images/how-to/openidm-ad-dj/0-ad-user-mapping.png[AD -++>++ managed user mapping]

Open the created mapping *systemAdAccounts++_++managedUser* and on the Properties tab configure the field mappings as shown in the table below.

[cols=",",options="header",]
|===
|*Source* |*Target*
|cn |cn
|description |description
|givenName |givenName
|mail |mail
|sn |sn
|telephoneNumber |telephoneNumber
|sAMAccountName |userName
|===

On the Behaviors tab, configure the behavior for different synchronization situations.

[cols=",",options="header",]
|===
|*Situation* |*Action*
|Ambiguous |Ignore
|Source Missing |Delete
|Missing |Ignore
|Found Already Linked |Exception
|Unqualified |Delete
|Unassigned |Ignore
|Link Only |Exception
|Target Ignored |Ignore
|Source Ignored |Ignored
|All Gone |Ignore
|Confirmed |Update
|Found |Ignore
|Absent |Create
|===

Save the changes.

On the Mappings tab, create another mapping as shown in the figure below

image:images/how-to/openidm-ad-dj/1-user-dj-mapping.png[Managed User -++>++ OpenDJ mapping]

Open the settings of the created mapping *managedUser++_++systemLdapAccounts* and on the Properties tab customize the field mappings as shown in the table below:

[cols=",,,",options="header",]
|===
|*Source* |*Target* |*Transformation script* |*Conditional updates*
|userName |uid | |
|sn |sn | |
| |cn |`source.cn {vbar}{vbar} (source.givenName {plus} ' ' {plus} source.sn)` |
|givenName |givenName | |
|mail |mail | |
|description |description | |
|telephoneNumber |telephoneNumber | |`object.telephoneNumber !== undefined && object.telephoneNumber !== null && object.telephoneNumber !== ''`
|===

For the `description` field, specify the default value `Created in OpenIDM`

On the Behaviors tab, configure the behavior for different synchronization situations:

[cols=",",options="header",]
|===
|*Situation* |*Action*
|Ambiguous |Ignore
|Source Missing |Delete
|Missing |Ignore
|Found Already Linked |Exception
|Unqualified |Delete
|Unassigned |Ignore
|Link Only |Exception
|Target Ignored |Ignore
|Source Ignored |Ignore
|All Gone |Ignore
|Confirmed |Update
|Found |Update
|Absent |Create
|===

On the same tab in the *Situational Event Scripts* section, add a script for the `onCreate` event.

[source,jsx]
----
target.dn = 'uid=' + source.userName + ',ou=People,dc=example,dc=com';
----

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-configure-opendj--active-directory-synchronization]]
=== Configure OpenDJ → Active Directory synchronization

Create OpenDJ → Managed User synchronization

image:images/how-to/openidm-ad-dj/2-dj-user-mapping.png[OpenDJ -++>++ Managed User Mapping]

In the Linked Mapping field, select *managedUser++_++systemLdapAccounts.*

Open the created mapping *systemLdapAccount++_++managedUser* and on the Properties tab customize the field mappings as shown in the table.

[cols=",",options="header",]
|===
|*Source* |*Target*
|mail |mail
|sn |sn
|givenName |givenName
|uid |userName
|telephoneNumber |telephoneNumber
|===

On the Behaviors tab, configure the behavior.

[cols=",",options="header",]
|===
|*Situation* |*Action*
|Ambiguous |Ignore
|Source Missing |Delete
|Missing |Ignore
|Found Already Linked |Exception
|Unqualified |Delete
|Unassigned |Ignore
|Link Only |Exception
|Target Ignored |Ignore
|Source Ignored |Ignore
|All Gone |Ignore
|Confirmed |Update
|Found |Ignore
|Absent |Create
|===

Create mapping Managed User → Active Directory

image:images/how-to/openidm-ad-dj/3-user-ad-mapping.png[Managed User -++>++ Active Directory Mapping]

In the Linked mapping field, select *systemAdAccounts++_++managedUser.*

In the created mapping *managedUser++_++systemAdAccounts* , configure the mapping:

[cols=",,",options="header",]
|===
|Source |Target |Transformation Script
|userName |dn |`'CN=' {plus} source {plus} ',CN=Users,DC=example,DC=com'`
|givenName |givenName |
|sn |sn |
| |cn |`source.displayName {vbar}{vbar} (source.givenName {plus} ' ' {plus} source.sn)`
|description |description |
|telephoneNumber |telephoneNumber |
|userName |sAMAccountName |
|===

On the Behaviors tab, configure the behavior similar to the step above.

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-verifying-the-solution]]
=== Verifying the solution

Confirm that each reconciliation completes without failures before running the next mapping. Enable deletion behaviors in the lab only after confirming that each mapping selects the intended entries.

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-active-directory-synchronization--opendj]]
==== Active Directory Synchronization → OpenDJ

In the administrator console, select the *systemAdAccounts++_++managedUser* mapping and click Reconcile.

image:images/how-to/openidm-ad-dj/4-systemAdAccounts_managedUser-recon.png[systemAdAccounts++_++managedUser Reconciliation]

In the admin console, navigate to the Manage → User list. Accounts from Active Directory will appear in the user list

image:images/how-to/openidm-ad-dj/5-manged-user-list-ad.png[Managed User List AD]

In the admin console, select the *managedUser++_++systemLdapAccounts* mapping and click Reconcile. After successful synchronization, the Active Directory records created in Managed Users will appear in OpenDJ.

Check if the account exists with the command

....
./opendj/bin/ldapsearch -p 1389 -b dc=example,dc=com  "(uid=aduser)" uid
dn: uid=aduser,ou=People,dc=example,dc=com
uid: aduser
....

[[configuring-openidm-for-synchronization-between-active-directory-and-opendj-opendj-synchronization--active-directory]]
==== OpenDJ Synchronization → Active Directory

In the admin console, under Configure → Mappings, select the *systemLdapAccount++_++managedUser* mapping and click Reconcile.

Navigate to Manage → User.

Accounts from OpenDJ will appear in the user list

image:images/how-to/openidm-ad-dj/6-managed-user-list-ad-dj.png[Managed User List Active Directiry and OpenDJ]

Next, select the *managedUser++_++systemAdAccount* mapping and click Reconcile.

After successful synchronization, accounts from OpenDJ will appear in Active Directory.

Verify their existence with the following command

....
LDAPTLS_CACERT=/path/to/ad-ca.pem ldapsearch -LLL -H ldaps://ad.example.com:636 -x -W \
  -D "CN=svc-openidm,CN=Users,DC=example,DC=com" -b "CN=Users,DC=example,DC=com" \
  "(sAMAccountName=bjensen)" dn
Enter LDAP Password:
dn: CN=bjensen,CN=Users,DC=example,DC=com
....
