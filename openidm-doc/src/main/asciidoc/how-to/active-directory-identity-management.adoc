[#active-directory-identity-management]
== Active Directory Identity Management

[[active-directory-identity-management-introduction]]
=== Introduction

In this article, we will configure Active Directory identity management from OpenIDM. Let's look at a typical scenario where HR hires a new employee, and enters their credentials into an account management system (IDM). From this system, the data must be imported into the main directory. Typically, this is Active Directory.

[[active-directory-identity-management-openidm-configuration]]
=== OpenIDM Configuration

How to quickly deploy OpenIDM was described in this xref:../getting-started/index.adoc[article]. Therefore, we will assume that you already have OpenIDM deployed.

[[active-directory-identity-management-active-directory-connector-configuration]]
==== Active Directory Connector Configuration

From the https://github.com/OpenIdentityPlatform/OpenIDM/tree/master/openidm-zip/src/main/resources/samples/provisioners[samples/provisioners] directory of the OpenIDM distribution, copy the `provisioner.openicf-adldap.json` file into the `openidm/conf` directory. Change the configuration values to match your environment:

In the administrator console select Configure → Connectors. In the list select AD LDAP Connector and set the settings according to the following table:

image:images/how-to/openidm-ad/0-openidm-ad-connector.png[OpenIDM LDAP Active Directory Connector]

[cols=",,",options="header",]
|===
|Setting |Description |Example value
|host |DNS name in the domain controller certificate |ad.example.org
|port |Active Directory port |636
|ssl |Use SSL connection |true
|principal |Dedicated account with delegated rights on the test OU |DOMAIN\svc-openidm
|credentials |Account password (string, after saving, the value will be encrypted) |
|baseContexts |One or more starting points in the LDAP tree that will be used when searching the tree. |CN=Users,DC=example,DC=org
|baseContextsToSynchronize |One or more starting points in the LDAP tree that will be used to determine if a change should be synchronized. |CN=Users,DC=example,DC=org
|accountSearchFilter |LDAP Filter for Retrieving Accounts |(&(!(userAccountControl:1.2.840.113556.1.4.803:=2))(!(objectClass=Computer)))
|accountSynchronizationFilter |An optional LDAP filter for the objects to synchronize. |(&(!(userAccountControl:1.2.840.113556.1.4.803:=2))(!(objectClass=Computer)))
|groupSearchFilter |LDAP Filter for Retrieving Groups |(objectClass=group)
|groupSynchronizationFilter |An optional LDAP filter for the objects to synchronize. |(objectClass=group)
|===

These account filters retain the sample configuration's exclusion of disabled accounts and computers.

Use LDAPS for the connection to Active Directory, including password updates. Obtain the CA trust anchor for the domain controller's certificate from your directory administrator and verify its fingerprint before importing it.

[source,bash]
----
keytool -importcert -alias ad-ca -file /path/to/ad-ca.pem \
  -storetype JKS -keystore /path/to/openidm/security/truststore
----

Use the absolute path of the truststore available to the Java process that runs the connector. Configure that process with `-Djavax.net.ssl.trustStore=/path/to/openidm/security/truststore` and `-Djavax.net.ssl.trustStoreType=JKS`, then restart it. For a remote connector server, configure its JVM. Verify the chain and hostname from the connector host and use *Test Connection* in the Admin UI before mapping passwords.

[source,bash]
----
openssl s_client -connect ad.example.org:636 -servername ad.example.org \
  -CAfile /path/to/ad-ca.pem -verify_hostname ad.example.org -verify_return_error </dev/null
----

Also, to synchronize passwords from OpenIDM, edit `objectTypes.account.properties` in the Active Directory connector configuration file `provisioner.openicf-adldap.json`. Add a comma after the closing brace of the existing `whenCreated` field, then add the `password` field:

[source,json]
----
"password" : {
    "type" : "string",
    "nativeName" : "__PASSWORD__",
    "nativeType" : "JAVA_TYPE_GUARDEDSTRING",
    "flags" : [
        "NOT_READABLE",
        "NOT_RETURNED_BY_DEFAULT"
    ]
}
----

[[active-directory-identity-management-openidm-and-active-directory-accounts-synchronization-configuration]]
==== OpenIDM and Active Directory Accounts Synchronization Configuration

In the administrator console, select Configure → Mappings. Click the New Mapping button.

image:images/how-to/openidm-ad/3-openidm-mappings.png[OpenIDM Mappings]

Into the source resource add Managed Object → user. Into the target resource add Connectors → ad.

image:images/how-to/openidm-ad/4-openidm-user-ad-mapping.png[OpenIDM User AD Mapping]

And click the Create mapping button

In the administrator console, select Configure → Mappings → managedUser++_++systemAdAccount

In the Attributes Grid, configure the attribute mapping according to the table:

[cols=",,,",options="header",]
|===
|Source |Destination |Transformation script |Conditional updates
|userName |dn |`'CN=' {plus} source {plus} ',CN=Users,DC=example,DC=org'` |
|givenName |givenName | |
|sn |sn | |
|description |description | |`!!object.description`
|telephoneNumber |telephoneNumber | |`!!object.telephoneNumber`
|userName |sAMAccountName | |
|password |password | |
|===

The sample connector marks `cn` as not creatable or updateable, so a separate `cn` mapping would be ignored. Active Directory uses the RDN from the `dn` mapping: for `userName` equal to `idmUser`, `cn` is `idmUser`.

On the Behaviors tab, under Policies, select Default Actions. Change the action for Source Missing (`SOURCE_MISSING`) from Exception to Delete, then click the Save button. This allows deleting a managed user to delete its linked Active Directory account; Default Actions alone leaves that account in AD.

The administrator then triggers the password reset from the existing user’s *Password* tab. For production onboarding, use a password reset link instead of sending a password. [[active-directory-identity-management-account-creation]]
==== Account Creation

Now that we have configured the connection to the Active Directory and synchronization between OpenIDM and AD accounts, let's test how the solution works. In the administrator console, select Manage → User and create a new account by clicking the New User button. Fill in the attributes of the new user and click Save.

image:images/how-to/openidm-ad/6-openidm-new-idmuser.png[OpenIDM new IDM user]

You can also create an account using OpenIDM REST API

[source,bash]
----
curl 'http://localhost:8080/openidm/managed/user?_action=create' \
 -H 'X-OpenIDM-Username: openidm-admin' \
 -H 'X-OpenIDM-Password: openidm-admin' \
 -H 'Content-Type: application/json' \
 --data-raw '{"mail":"jdoe@example.org","sn":"Doe","givenName":"John","telephoneNumber":"+7(999)123-45-67","userName":"idmUser"}' | json_pp

[[active-directory-identity-management-sending-password-by-email-1]]
==== Sending Password by Email

If you want to set a random password for Active Directory, go to the Password tab and click the Email Random Password button.

image:images/how-to/openidm-ad/7-openidm-email-random-password.png[OpenIDM Email Random Password]

----
curl 'http://localhost:8080/openidm/managed/user/a250eb09-28a1-4fab-b338-e729986f38ec?_action=resetPassword' \
 -X 'POST' \
 -H 'X-OpenIDM-Username: openidm-admin' \
