[#chap-overview]
== Overview of the OpenIDM Samples

The OpenIDM ZIP includes sample projects under `openidm/samples/`.
Use the directory names below to find the files in the distribution.
See xref:#install-samples[Installing the Samples] and xref:#preparing-openidm[Preparing OpenIDM] before running a project.

[#install-samples]
=== Installing the Samples

Extract the OpenIDM ZIP and run the launcher from the `openidm/` directory. Pass a sample directory to `-p` to load its project configuration. The following command starts the XML reconciliation project.

[source,console]
----
$ cd /path/to/openidm
$ ./startup.sh -p samples/sample1
----

On Windows, use `startup.bat -p samples\sample1`. When the guide refers to `sample1/conf/`, the path is relative to `openidm/samples/`.

Follow each project's instructions for external services, connector bundles, and test data before starting OpenIDM. The reusable files listed above are copied into a test project individually. See xref:../integrators-guide/chap-configuration.adoc#changing-configuration[Changing the Default Configuration] for how project configuration is loaded.

[#preparing-openidm]
=== Preparing OpenIDM

Install an instance of OpenIDM specifically to try the samples. That way you can experiment as much as you like, and discard the result if you are not satisfied.

`-p` selects the configuration directory. The default embedded OrientDB database remains under the installation's working directory, so different sample projects can share repository state. Use a fresh test installation for each independent scenario, or stop your test instance and move its `db/openidm` directory to an unused backup path before switching scenarios. If you configure a JDBC repository, use a separate test database or schema for each scenario.

For a number of the samples in this guide, users are created either with the UI or directly with a commons REST call. Users that have been created in the repository (managed users) should be able to log into the Self-Service UI.
